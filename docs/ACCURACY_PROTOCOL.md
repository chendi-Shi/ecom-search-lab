# v0.3 准确率改进协议

目标是提高商品相关性排序。生成式检索在旧实验中明显落后，继续作为研究对照；本轮将算力集中到能够直接比较需求与商品文本的 CrossEncoder，以及学习其与词法约束关系的 LambdaMART。

## 数据与隔离

数据来自固定版本 Amazon ESCI。新数据排除旧实验所有查询 ID 和归一化查询，保留 82,427 个真实商品，2,000 个训练查询、200 个验证查询、200 个封存测试查询。每个查询保留全部官方已标注候选，至少 20 个；不同查询的候选数量不同。详细来源、哈希、抽样步骤见 `DATA_V2.md`。

为了控制普通 CPU 成本，排序训练从 2,000 个训练查询中按预先指定的哈希选取 500 个，使用其全部人工标注候选。没有将未标注商品当作训练负例，也没有生成伪相关性标签。模型可以看到商品目录文本及其词频，不能在选择参数时使用测试标签。

## 固定比较

- **BM25**：当前目录的标题词频统计。
- **Transferred pairwise**：旧 12 特征模型的冻结权重，应用到当前目录的无标签词频统计。不是重新训练的基线，也不能与旧 20 候选测试数字直接纵向比较。
- **CrossEncoder**：冻结 `cross-encoder/ms-marco-MiniLM-L6-v2`，同时读取 Query 和 `title + ". Brand: " + brand`；固定 128 token 截断。
- **LambdaMART**：12 个词法/品牌/数字/否定特征，加 CrossEncoder 原始相关性分数、同一查询候选池内的分数百分位与总体标准分，共 15 维。百分位采用并列分数的平均名次，标准分在全组相同时置零。这两个相对特征只使用候选分数，不读取相关性标签。LightGBM 训练后导出数值树；服务不需要 LightGBM。

本轮采用 CPU `dynamic_int8` 精度，固定 oneDNN 量化引擎。它是独立的实验配置，并不与 float32 无损等价；训练、验证、测试和服务都使用该配置重新计算的分数。动态量化的激活范围依赖 batch 内其他商品，因此缓存绑定一次调用的完整有序 Query/商品列表，不能跨候选集复用单商品分数。

候选方案只用验证集选择：CrossEncoder 单独使用，或 LambdaMART 的叶子数 `[7,15]` 与迭代数 `[50,100,200,400]`。其余参数固定：学习率 0.05，叶子最少 40 条，L2=1，随机种子 20261010，CPU 2 线程。预测相同分数时按商品 ID 升序排序。导出树的预测必须与训练库原始预测在 1e-12 容差内一致。

相对特征依赖完整候选池：不能先截取前五名再计算，也不能将某商品在另一查询或另一候选池中的百分位拿来复用。人工候选评测与全库召回 top100 的分数分布可能不同，因此另做相同召回池上的评测，不能用人工候选成绩代替真实召回成绩。

## 开发过程披露

15 维方案是在原 13 维模型完成第一轮验证选模后追加探索得到的，并非一开始就确定的唯一方案。整个扩展阶段尚未打开本轮封存测试标签；沿用相同 500 条训练查询、200 条验证查询、冻结的 CrossEncoder 分数及超参数网格。

| 特征方案 | 维数 | 验证 NDCG@10 | 本轮选择 |
|---|---:|---:|---|
| 初始：12 词法特征 + CE 原始分数 | 13 | 0.7426062 | 初始对照 |
| A：初始特征 + 池内 CE 百分位/标准分 | 15 | 0.7481696 | 7 叶、200 轮 |
| B：A + 旧 pairwise 分数/查询长度 | 17 | 0.7464171 | 未采用 |

A 相对初始方案的验证 NDCG 增加 0.0055634。三种特征组各比较同一 8 点网格，另比较独立 CrossEncoder；重复使用验证集会增加选择偏差。这些数字是开发依据，不能作为未见查询上提高的最终证据。采用 A 后重新冻结模型、特征源码和协议，最终泛化结论只能来自随后按冻结配置执行的测试。

`outputs/accuracy-v1/validation_feature_probe.json` 保留完整 A/B 网格与输入哈希；`development-initial/` 保留初始模型、选择、协议、验证结果与特征缓存元数据。交付不包含其 `.npy` 或分数缓存。初始开发产物仅用于审计，不能直接与最终 15 维服务源码混用。

主要指标是按查询宏平均的 **NDCG@10**：E/S/C/I 对应等级 3/2/1/0，增益为 7/3/1/0。辅助指标为前十 E/S 比例、第一位 E 的比例、已知 E/S Recall@10。没有非零理想 DCG 的查询只从 NDCG 分母排除；其他指标各自报告分母。NDCG 是排序质量指标，不是分类准确率。

## 冻结与最终评估

`scripts/train_accuracy.py select` 只解析 train/val。选定模型后，保存模型、参数、数据文件 SHA、特征与评估源码 SHA、运行协议 SHA。测试文件此时只计算字节哈希，不读取其标签进行统计或评分。

`scripts/train_accuracy.py final` 首先校验冻结文件，再写入 final lock，之后才解析测试标签。中断后只能以完全相同的配置与模型恢复，不得根据测试成绩重新调参。最终比较使用同一批完整人工候选。按查询配对 bootstrap 10,000 次，固定种子，报告 95% 区间；同时保留逐查询结果。

服务中的全库召回是另一个评估范围。默认固定词法候选池后做精排；从这 200 个测试查询中，按预先指定的查询 ID 哈希选取 50 个，比较相同 top100 召回候选的排序。全库中未标注商品的真实相关性未知。只能报告已知正例 Recall 和标注覆盖率，不能将未标注全部当错误后声称真实全库准确率。完整向量重建可从 checkpoint 续跑，未完成产物不会进入默认服务或交付包。

## CPU 成本与复现

目录的词频、平均标题长度和品牌集合使用完整目录；字符集合等商品特征采用按需 512 条 LRU。该实现与原特征逐值相等，避免为八万商品预存大量 Python 集合。CrossEncoder 分数缓存绑定精确输入、模型/分词器哈希、数值配置、运行库版本与源码；缓存不跨不兼容模型复用。

运行时依赖与 CPU 数值配置属于冻结实验的一部分。`requirements-accuracy.txt` 记录本次实际 CPU 解释器中查询到的运行库精确版本；建议使用独立 Python 3.10 环境，从项目根目录安装后运行：

```powershell
python -m pip install -r requirements-accuracy.txt
python -m pip install --no-deps -e .
$env:ECOM_SEARCH_PYTHON = (Get-Command python).Source
.\run-accuracy.ps1
```

依赖安装需要网络或对应的本地 wheel；下载来源需能提供清单中的精确版本。清单用于服务推理，LightGBM 4.7.0 是重新训练时的附加依赖。`pyproject.toml` 的 `full,training` 范围仅描述功能依赖，任意满足范围的版本不保证与已冻结模型兼容。

CE fingerprint 严格绑定运行库版本、量化配置、模型/分词器和适配器源码。即使版本号一致，平台仍需支持冻结的 `onednn` 量化后端；检查失败时应恢复匹配环境，或以新配置重新走 train/val/冻结/最终评测，不能通过修改已冻结元数据绕过检查。同一解释器下的异目录离线交付核验不代表所有操作系统或 CPU 都产生相同数值。首次模型加载、未缓存推理、已缓存查询的延迟应分别报告。
