# 实际 CPU 实验

本文件保留首轮文本排序与检索对照，并追加 int8 资源审计；v0.2 的多模态、个性化与生成式实验汇总见 [完整版本结果](EXTENDED_RESULTS.md)。最新测试数量以 `outputs/verification.json` 为准。

实验日期：2026-10-09。保留原始 JSON、模型、输入指纹和逐 Query 结果。这里的排序是本项目冻结候选实验；公开商品池检索另列，不能把两者混为同一召回指标。

## 学习排序

250 train / 50 val / 100 test Query，每条固定 20 个独立人工标注候选。标题/品牌商品池 15,171；grade=E/S/C/I→3/2/1/0，gain=`2^grade-1`。固定 0/5/15/30 轮仅根据 val 选择 30 轮，测试评分前模型已冻结。

| 最终测试指标 | 标题 BM25 | Pairwise 学习排序 | 绝对变化 |
|---|---:|---:|---:|
| NDCG@10，100 Query | 0.731488 | 0.760554 | +0.029067 |
| 固定候选 Recall@10，100 Query | 0.517294 | 0.538324 | +0.021030 |
| 长 Query NDCG@10，39 Query | 0.723431 | 0.770147 | +0.046716 |

长 Query 定义为至少 5 个词，并非人工标注的语义难度。训练和选择加最终评测总耗时约 200.84 秒；这是本机当前负载下的一次运行。改动是字段/属性特征与 pairwise 学习，不证明论文创新、统计显著性或线上收益。逐条提升和回退均保留在 [差例文件](../outputs/ranking/per_query_test.jsonl)。

## 真实向量索引

预训练 `paraphrase-MiniLM-L3-v2`、CPU、相同归一化商品向量，15,171 商品；50 条验证 Query 从 efSearch 32/64 中按邻居 Recall@10 选 64，再使用 100 条 test。HNSW M=16、efConstruction=80。

| 指标 | FlatIP | HNSW |
|---|---:|---:|
| 与 exact 前十邻居重合率 | 1.0000 | 0.9900 |
| 已知 E/S 正例 Recall@100 | 0.725922 | 0.727402 |
| 判定覆盖率@100 | 0.2780 | 0.2792 |
| 检索 p50，毫秒 | 23.086 | 1.092 |
| 检索 p95，毫秒 | 70.664 | 1.464 |
| 索引文件大小，MB（十进制） | 23.303 | 25.490 |
| 索引构建时间，秒 | 0.020 | 10.255 |

向量时延只含已编码 Query 向量的归一化、FAISS 搜索和 ID 映射；不含文本编码或学习排序。HNSW 更大的索引和构建成本换取较低查询耗时。近似 Top100 恰好包含更多已标正例，不能解释为 HNSW 的语义模型更好。99% 是对 exact 的邻居重合率，不是购物搜索准确率。

首次运行的选择记录 `selection.json` 原样保留，其中 known-positive 仪表最初含 C；ef 参数始终只依据邻居一致率，与该二值定义无关。随后在同一冻结图和参数上按 E/S 统一复算，最终 [report.json](../outputs/ann/report.json) 记录了更正、指纹、验证和测试指标；没有重新选择 ef 或重建图。最终指标以 report 为准。

## 磁盘向量与显式工作区

同一 MiniLM 向量另比较 float32 与逐行 int8 的 mmap 分块扫描。验证集选择 chunk=4096；这是对归一化向量或量化重建向量的扫描，不是新的 ANN 算法，也没有验证分布式存储或千亿规模。

| 指标 | float32 磁盘向量 | int8 磁盘向量 |
|---|---:|---:|
| 向量/ID/scale backing 文件合计，MB（十进制） | 23.606 | 6.190 |
| 与 exact 前十邻居重合率 | 1.000 | 0.998 |
| 已知 E/S 正例 Recall@100 | 0.725922 | 0.725922 |
| 原实测检索 p95，毫秒 | 34.998 | 47.587 |
| chunk=4096 显式 ndarray 工作区保守上限，字节 | 6,565,888 | 6,565,888 |

int8 backing 较小，当前实测 CPU 延迟较高。工作区估计 v2 采用 `4*chunk_rows*dimension + 64*chunk_rows + 32*dimension`，覆盖解码块、分数/partition/mask/边界索引及 Query 归一化的 float64 临时数组；不含 OS 页面缓存、BLAS 内部空间、Python 对象或模型权重，因此不是进程 RSS 上限。

原实验后修复了 mmap 显式释放及 Top-k 并列分数跨 chunk 的确定性，并更正工作区估计。原选择 chunk、质量指标和延迟均保留，没有重跑参数选择；使用同一份已缓存的 100 条 test Query 向量单独核验，新 tie 策略的前十邻居重合率仍为 **0.998**。该检查不加载或训练编码器，也不将旧延迟视为修复后重新测量。原工作区口径保存在报告的 `workspace_original_estimate`，说明与缓存指纹见 [磁盘报告](../outputs/disk-vectors-v1/report.json) 和 [测后邻居核验](../outputs/disk-vectors-v1/post_measurement_neighbor_check.json)。

## 倒排与演示

SQLite FTS5 索引文件 5,259,264 字节，构建约 0.785 秒，查询页面缓存上限 8 MiB。整合 Query 解析后，排除条件依据标题中的肯定/否定词项做字面检查；避免直接 NOT sugar 丢掉 sugar-free 商品。规则有词义和缺失属性边界，不能把文案推断当作真实商品合规验证。

倒排运行版本和计时结果在 [retrieval-v4.json](../outputs/retrieval-v4.json)。历次检索逻辑修正的旧报告保留，不能混用其指标。倒排包含商品文本取回，而 ANN 延迟排除了编码，两者计时范围不同，不作直接速度倍数比较。服务单独记录包含编码/召回/重排的端到端搜索耗时。
