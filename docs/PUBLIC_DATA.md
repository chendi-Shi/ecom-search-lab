# Reproduce a new experiment from official ESCI data

`scripts/prepare_public_esci.py` creates a standalone research dataset directly from Amazon's official Parquet files. It does not need the author's original prepared subset. The input is real US English product search queries, title/brand metadata, and human E/S/C/I relevance judgments. No examples are hand-authored, generated by an LLM, or assigned pseudo-labels.

This is a **new public protocol**, `public-esci-v1`. The historical `reports/accuracy/` results used a different query selection with previous-experiment exclusions. This command does not reproduce those exact historical numbers and does not claim its queries have never appeared in another experiment. Within a new run, train, validation, and test are disjoint by official query ID and normalized query text. Keep test scores sealed until configuration selection on validation is finished.

## Prepare

Python 3.10+ and `pyarrow` are required for Parquet import. The subsequent lightweight search/benchmark needs no neural model download. Install PyArrow in your chosen environment, then run from the repository root:

```powershell
python -m pip install -r requirements-public.txt
python scripts/prepare_public_esci.py --download --output data/esci-public
```

The explicit `--download` flag fetches about **1.16 GB** from the pinned official repository into `data/raw/esci`. Allow space for both downloaded data and temporary download verification (about 2.3 GB), plus the prepared subset. Existing files are SHA256 checked; a mismatch fails without silently replacing a local file. Without `--download`, the command is offline and requires existing official files:

```powershell
python scripts/prepare_public_esci.py --raw data/raw/esci --output data/esci-public --train-queries 1000 --val-queries 100 --test-queries 100 --min-candidates 20 --seed 20261011
```

For a smaller real-data smoke run, specify `--train-queries 100 --val-queries 20 --test-queries 20` and a **different output directory**. Source verification still reads the complete files. Import streams Parquet column batches and does not load the full product table in memory. No model or neural training is involved. An existing output directory is always rejected, including an empty directory. If a preparation run is interrupted, inspect that directory and use a new output path for the retry; partial output has no completed manifest and is not a valid dataset.

## Selection and evaluation contract

1. Verify both complete source files against their pinned SHA256 and size. Read only `query_id`, `query`, `product_id`, `product_locale`, `small_version`, and `split` while selecting queries; `esci_label` is not projected from Parquet in this pass.
2. Use US rows with `small_version=1`. Normalize queries with Unicode NFKC, casefold and collapsed whitespace. Exclude any normalized query present in both official train and test partitions. Count distinct judged products per query; require at least `--min-candidates` without inspecting grades.
3. Pick one deterministic representative for duplicate normalized queries. Sort eligible identities with SHA256 of canonical JSON `[seed, tag, value]`. Choose train and validation from the official train partition, and test from official test. Persist `selection.json` before reading labels. All counts and identities depend only on metadata.
4. Retain **every original judged product** for each selected query, including irrelevant products. Copy E/S/C/I to grades 3/2/1/0 exactly; reject conflicting labels or missing metadata. Candidate order is also label independent. There is no fixed-size, relevance-stratified candidate sampling.
5. Build the catalog as the union of these judged product IDs, with official title and brand. Catalog membership does include unlabeled-for-training test product identities and metadata; this is an offline searchable inventory, not an inductive new-product benchmark. The catalog is not all of Amazon. Cross-query pairs usually lack judgments, so a full-catalog result reports **known-positive recall** and judged coverage rather than pretending unjudged products are known negatives.
6. Freeze `manifest.json` with source hashes, selection hash, settings, importer hash and the size/SHA256 of every prepared file. The manifest contains no local absolute paths or timestamps. Do not tune the seed or query counts after observing test results.

The output contains `catalog.jsonl`, `train.jsonl`, `val.jsonl`, `test.jsonl`, matching `corpus_*.jsonl`, `selection.json`, and `manifest.json`. Closed-pool records contain `query_id`, `query`, `split`, `candidate_ids` and one integer `qrels` grade for every candidate. Corpus records use an empty candidate list and the same known qrels. Ranker training/selection must read train and validation files directly: the convenience `load_dataset` function loads test too and should be reserved for final evaluation or integrity checks.

The importer has adversarial tests for normalization leakage, source corruption, grade-blind selection, complete qrels, conflicting identities/annotations, overwrite refusal, and byte-identical preparation of a tiny actual Parquet fixture. Run:

```powershell
python -m unittest discover -s tests -p test_public_esci.py -v
```

The Parquet integration case skips if PyArrow is unavailable; the remaining protocol tests use only the standard library. These small fixtures validate the importer contract, not model relevance. The benchmark's real-data results must be reported separately.
